## 与发布模块的数据约定

所有功能共用 `CampusPosts.STORAGE_KEY`，其值为 `campus-lost-found.posts.v1`。对应的 `localStorage` 值是 **JSON 数组**，一条信息的格式如下：
json
{
"id": "post-001",
"type": "lost",
"name": "黑色长柄雨伞",
"category": "雨伞",
"place": "图书馆一楼",
"time": "2026-10-07T08:10",
"createdAt": "2026-10-07T09:00:00+08:00",
"status": "寻找中",
"desc": "伞柄有银色金属环。",
"contact": "微信：example",
"ownerId": "发布者标识"
}
- `id` 是非空字符串或有限数值，在整个数组内唯一；其他模块可以添加所有者等字段。
- `type` 为 `lost`（寻物）或 `found`（招领）。
- 寻物状态为 `寻找中` / `已找到`；招领状态为 `招领中` / `已归还`。
- `time` 是丢失/拾取时间；`createdAt` 是发布时间。首页按发布时间降序排列；兼容缺少 `createdAt` 的原型数据，此时按 `time` 排序。带时区的 ISO 时间在界面上转换为北京时间，不带时区的表单时间按原值显示。
- `name`、`category`、`place`、`time`、`desc` 为字符串。`contact` 可为空，此时详情应提示未提供联系方式。
- `ownerId` 由 `manage.js` 自动生成并绑定到本地身份，用于隔离不同用户的发布内容。
- 写入或更新成功后，在同一窗口派发 `window.dispatchEvent(new Event('campus:posts-changed'))`，列表会重新读取。其他窗口的存储变化通过 `storage` 事件更新。
- **演示数据始终作为预置内容存在**（打 `_demo: true` 标记），不受用户真实发布影响；首次没有真实数据时显示演示信息，发布后演示数据与真实数据合并展示。
- 读取失败或数据损坏时显示明确提示并使用演示信息，保留原始存储供排查。

直接打开 HTML 时，存储与浏览器配置、文件路径有关。联调时保持同一个 `index.html` 入口，在 Chrome 中验证刷新后的数据。发布模块已处理存储失败，保存失败不会跳转成功页。

## 剩余限制

- **无后端服务**：数据仅存于本地浏览器 `localStorage`，不同设备/浏览器之间不共享。
- **无多端同步**：同一台电脑不同浏览器（Chrome/Firefox）数据独立。
- **无权限体系**：`ownerId` 基于本地生成，用户清除浏览器数据后身份重置，可重新认领（通过相同浏览器）。
- **存储容量有限**：`localStorage` 通常限 5MB，大量图片（当前仅文本）会触顶。
- **无实时通知**：状态变更仅同标签页通过事件刷新，跨标签页依赖 `storage` 事件。
- **测试环境依赖**：新增白盒测试需在 Node.js 环境中运行，当前已设计但尚未写入文件。
- **Chrome 控制连接**：验证时若 Chrome 控制连接不可用，交互走查需使用应用内浏览器替代。

## 剩余限制

- **无后端服务**：数据仅存于本地浏览器 `localStorage`，不同设备/浏览器之间不共享。
- **无多端同步**：同一台电脑不同浏览器数据独立。
- **无权限体系**：`ownerId` 基于本地生成，用户清除浏览器数据后身份重置。
- **存储容量有限**：`localStorage` 通常限 5MB，大量数据会触顶。
- **无实时通知**：状态变更仅同标签页通过事件刷新，跨标签页依赖 `storage` 事件。
- **测试代码待写入**：新增白盒测试已设计用例，尚未写入 `tests/` 文件，需在 Node.js 环境中运行验证。
- **Chrome 控制连接**：验证时若控制连接不可用，交互走查需使用应用内浏览器替代。
